What this demo simplifies

  • Longitudinal motion between events is straight-line, constant-velocity extrapolation — trajectory and teleport actions mid-scenario aren't simulated.
  • Lane position is schematic (lane index × 3.5 m, straight road, heading always 0) unless a matching .xodr is loaded in step 2 — then it's resolved onto the real road centerline and lane width, with heading following the road tangent.
  • OpenDRIVE support covers line and arc geometries exactly, and spiral (clothoid) by numeric integration; poly3 / paramPoly3 segments fall back to a straight-line approximation. Road laneOffset and elevation/superelevation profiles aren't applied — the world stays flat (z = 0).
  • Junctions and road-to-road transitions aren't resolved — an entity stays on the single road it was initialized on for the whole scenario.
  • Only SimulationTimeCondition triggers resolve to a real time. Distance, speed, TTC, story-element-state and other trigger types can't be evaluated — those events are applied at t = 0 instead of being skipped, so the storyboard still animates (flagged as "unresolved — applied at 0.0s" in the Events table).
  • Relative speed/lane targets are approximated against the referenced entity's initial state, not a live multi-entity simulation.
  • Catalog-referenced vehicles without an inline bounding box use estimated default dimensions.
  • Acceleration and orientation-rate are never populated — OSI's base.acceleration / base.orientation_rate stay implicitly zero.
  • No host_vehicle_id is designated — this tool doesn't distinguish an ego vehicle from other entities.

Convert to real OSI structure

Re-shapes the readable JSON above into the actual osi3.GroundTruth message structure — real field names (movingObject, base.orientationRate, …), real enum values, Identifier/Timestamp wrapper messages, and 64-bit fields as strings, per protobuf's standard JSON mapping. Opens in a new window with its own preview and download button.

Not the compact binary .osi wire format — that needs the compiled OSI protobuf schema and a protobuf runtime, which this single self-contained HTML file intentionally doesn't bundle.

All parsing, generation and playback happen locally in this page — no scenario data is uploaded anywhere.
